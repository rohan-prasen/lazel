# Issue trackers

Use [GitHub Issues](https://github.com/rohan-prasen/lazel/issues) for public bug reports and feature requests. Use the Lazel project in Linear's Solo (`SOLO`) team for specs, implementation tickets, and roadmap work.

Read and triage a referenced ticket in its original tracker. Use `gh` with `--repo rohan-prasen/lazel` for GitHub and the Linear connector with team `SOLO` and project `Lazel` for Linear.

Publish new engineering specs and tickets to Linear by default. If a user explicitly requests GitHub, publish there. Search for an existing ticket before creating one. When approving implementation of a GitHub report, link the GitHub URL from the Linear ticket and keep public discussion in GitHub.

Use native parent and blocking relationships in the tracker that owns the work. For `/wayfinder`, keep the map and its child tickets in that tracker and use the earliest unassigned child with all blockers resolved.

**PRs as a request surface: no.**
