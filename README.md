Lazel (*lazy + Bazel*) is a Rust task runner for mixed-language monorepos. Define your existing build, test, and lint commands in one `lazel.toml`, then run them in dependency order from a project directory on macOS, Linux, or Windows.

## Install

Both installers support x86-64 and ARM64. They download the latest release, verify its SHA-256 checksum, and print PATH instructions when needed.

### macOS and Linux

```sh
curl -LsSf https://raw.githubusercontent.com/rohan-prasen/lazel/main/script/install.sh | bash
```

Lazel installs to `$HOME/.local/bin`. Add it to your current shell's `PATH` if needed and verify the installation.

```sh
export PATH="$HOME/.local/bin:$PATH"
lazel --version
```

### Windows

Run this in PowerShell. The [latest release](https://github.com/rohan-prasen/lazel/releases/latest) must include the Windows ZIP for your architecture and its `.sha256` file.

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/rohan-prasen/lazel/main/script/install.ps1 | iex"
```

Lazel installs to `%USERPROFILE%\.local\bin`. Add it to your current PowerShell session's `PATH` if needed and verify the installation.

```powershell
$env:Path = "$env:USERPROFILE\.local\bin;$env:Path"
lazel --version
```

## Update Lazel

Run `lazel update` or `lazel upgrade` from any directory. Either command checks
the latest stable GitHub release and installs it if it is newer. Lazel verifies
the archive checksum and the new executable's version before replacing your copy.

Self-update applies to the per-user locations above. For other locations, use
the original installation method. If you have Lazel 0.1.3 or earlier, rerun your
installer once to get the update commands.

On Windows, Lazel keeps the previous executable as `.lazel-update.previous.exe`
beside `lazel.exe`. If an interrupted update leaves `lazel.exe` missing, close
any running Lazel processes and rename the backup to `lazel.exe`, or rerun the
installer.

See the [changelog](CHANGELOG.md) for release details.

## Try it

On macOS or Linux, run these commands from the repository root with stable Rust and Python 3 installed.

```sh
cargo build --locked
cd examples/mixed-language
export LAZEL_RUST_VERSION="$(rustc --version --verbose)"
export LAZEL_PYTHON_VERSION="$(python3 --version)"
../../target/debug/lazel run app:build
python3 app/build/app.pyc
```

Lazel builds the Rust generator before running the Python build. The compiled Python app prints `generated by Rust`. Run the same task again from `app/` with `../../../target/debug/lazel run app:build` to see both cache hits. Lazel can restore the build directories if you delete them and run the task again.

## Configure a workspace

Place `lazel.toml` at the workspace root. Lazel uses the nearest config it finds by walking up from the current directory, including across Git boundaries.

```toml
[projects.generator]
dir = "generator"

[projects.generator.tasks.build]
command = "mkdir -p build && rustc main.rs -o build/generate"

[projects.app]
dir = "app"

[projects.app.tasks.build]
command = "python3 build.py ../generator/build/generate"
depends_on = ["generator:build"]
```

- `dir` is a path relative to the workspace root, such as `app` or `.`. It must resolve to an existing directory inside the workspace.
- `command` is a nonblank shell command run from the project directory. Use `/bin/sh` syntax on macOS and Linux and `cmd.exe` syntax on Windows. Commands inherit your environment, standard streams, and privileges. Run tasks only from workspace configurations you trust.
- `depends_on` is an optional list of `project:task` identifiers. Project and task names start with a lowercase ASCII letter and can also contain digits, hyphens, and underscores.

Run a task with `lazel run <project>:<task>`. Lazel validates the whole workspace first, completes prerequisites sequentially in declaration order, and processes shared prerequisites once per invocation. On failure it stops and returns the shell's exit status. Lazel writes its progress and diagnostics to stderr.

### Cache a task locally

Add these fields to a task block to reuse its successful result when the declared inputs are unchanged.

```toml
cache = true
inputs = ["src/**/*.rs", "Cargo.toml", "Cargo.lock"]
outputs = ["dist"]
env = ["RUST_TOOLCHAIN_VERSION"]
```

- `inputs` is a nonempty list of project-relative file globs. Use `/` as the separator. Lazel skips its cache, Git metadata, and the task's own outputs. Declare generated inputs after their producing task in `depends_on`, and include files such as lockfiles that can change the result.
- `outputs` lists literal files or directories the task owns. A cache hit can replace an entire declared directory, including stale files inside it. Use a dedicated output directory for each task. Omit `outputs` for checks that produce no files.
- `env` lists environment variables the command can read and Lazel hashes. Lazel also passes and hashes `PATH` and, on Windows, `SystemRoot` and `PATHEXT` when set. Supply toolchain versions through declared environment variables or input files. Keep tasks that depend on undeclared machine or network state uncached.

Lazel stores successful results under `.lazel/cache/` in the workspace root. Add `.lazel/` to the workspace's Git ignore rules. Cache hits, misses, and bypasses appear on stderr. On a hit, Lazel restores the files and skips the recipe. Use `lazel run --no-cache <project>:<task>` to run all selected recipes with the inherited environment and bypass cached results.

An interrupted restore can leave the previous outputs in `.lazel/restoring/backup/`. In `.lazel/restoring/manifest.toml`, `project` identifies the project directory and `roots` lists the output paths in backup index order. Recover those outputs before clearing the restore directory.

On Windows, save this example as `lazel.toml` in a folder on a local drive and run `lazel run app:hello` from that folder.

```toml
[projects.app]
dir = "."

[projects.app.tasks.hello]
command = "echo Hello from %COMPUTERNAME%"
```
